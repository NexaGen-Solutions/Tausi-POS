## Part A — Reports on the terminal

**Route:** `/pos/reports`, reached from a **Reports** button in the table map's top bar, next to My sales. The button shows for users with `reports.own` or `reports.all`.

**Three reports,** using the same report classes and the shared sales helper as the admin site (Task 13). Don't create a second set of calculations.
1. **Sales by user:** each user's total, tickets, gifts, voids and discounts, with a tap to expand into their items (ticket, time, item, qty, amount).
2. **Daily sales:** for the chosen date or dates, gross sales, discounts, net, VAT, payments by type (cash, M-Pesa, card), number of tickets, average ticket, open tickets (count and value), voids and gifts.
3. **Sales by item:** grouped by category, with quantity and amount, plus gifts and voids.

**Revenue only, for everyone:** the terminal reports show **sales figures only**. There's no cost, margin, profit, cost of sales or stock value, even for admins. Those stay on the admin site's reports, which don't change.

**Who sees what:**
- Users with only **`reports.own`** (waiters, by default) see **only their own figures** in every report: their row in Sales by user, and their own items in Sales by item and Daily sales. The screen header says "Only your own figures".
- Users with **`reports.all`** (supervisors and admins, by default) see everyone.
- This is enforced on the **server**, and a test proves a waiter can't get other users' data by changing the request.

**Filters,** kept simple for touch:
- **Today** / **Yesterday** / **This week** / **Pick dates** (from and to, on a touch calendar)
- **User**, for `reports.all` only
- **Terminal**, for `reports.all` only

**Layout:**
- Big touch-friendly tabs for the three reports.
- Totals in large monospace at the top, and a scrollable table underneath.
- Long names **wrap**, never cut.

**Print:** **Print** sends a 42/32-column slip of the report on screen to this terminal's receipt printer, with the business name, the report name, the dates, who printed it and when. Reuse the 🧾 receipt versions from Task 13, and add one for **Daily sales** if it doesn't exist.

**Idle logout** applies as on every other POS screen.

**Permissions:** no new keys. `reports.own` and `reports.all` now also control these terminal screens. Update the help text in the Permissions grid.


**Dates:** use the date filters from 17a (Today, Yesterday, This week, Pick dates), so the terminal reports match the admin site for the same dates.
